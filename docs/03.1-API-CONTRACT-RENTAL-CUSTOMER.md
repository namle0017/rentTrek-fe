# 03.1 — API Contract: Khách hàng thuê thiết bị

> Phần mở rộng của [`03-API-CONTRACT.md`](03-API-CONTRACT.md) cho luồng **khách hàng thuê thiết bị** (Guest xem danh mục, Customer đặt / thanh toán / theo dõi / hủy đơn thuê).
> Wrapper, paging, mã lỗi chung, quy ước URL/JSON theo [`01-CONVENTIONS.md`](01-CONVENTIONS.md). Khi được duyệt, gộp các mục dưới đây vào `03-API-CONTRACT.md` và ghi Changelog.
>
> Căn cứ: schema `database/supabase_schema.sql` (22/10/2026) và PRD RenTrekk v0.1 (FR-P, FR-R, FR-C, FR-F, FR-M; BR-02, BR-13…BR-23).
> Không bao gồm: API cho Staff/Admin (giao nhận, lập phí, duyệt hoàn, quản lý danh mục), đặt tour, đánh giá, gia hạn (FR-R09 — P1).

> **Cập nhật chính thức — đã gộp vào `03-API-CONTRACT.md`:**
> - Các mục **4.4–4.6** (combo, kiểm tra khả dụng), **5.1–5.4** (báo giá, tạo đơn, đơn của tôi, chi tiết đơn) và **6.1–6.2** (khởi tạo và theo dõi thanh toán VietQR) đã được triển khai đầy đủ trên Backend và gộp vào [`03-API-CONTRACT.md`](03-API-CONTRACT.md).
> - **Chính sách tiền cọc:** Hệ thống áp dụng chính sách **không thu cọc** (`depositAmount = 0`, `totalPayable = totalAmount`).
> - **Idempotency & Pickup:** Header `Idempotency-Key` được lưu tại `orders.idempotency_key`; thông tin `pickup` được định dạng gộp vào trường `orders.note`.
> - **Chuyển khoản SePay:** `transferContent` sinh theo mẫu `RTP` + 16 ký tự hex đầu của `paymentId`.
> - **3 API chưa triển khai trên Backend:** Mục **5.5** (xem trước hoàn tiền khi hủy), **5.6** (khách hủy đơn thuê) và **5.7** (khiếu nại phí) hiện Backend chưa có endpoint; Frontend tạm thời duy trì mock data/fallback cho 3 luồng này.
> - Các mục **4.1–4.3** sử dụng theo API Catalog chuẩn tại [`03-API-CONTRACT.md` §5](03-API-CONTRACT.md#5-products).

## Quy ước riêng cho luồng thuê

1. **Mọi số tiền do server tính** (BR-02). FE chỉ gửi biến thể/combo, số lượng, thời gian, mã khuyến mãi. Mọi field tiền trong request (nếu FE lỡ gửi) bị bỏ qua.
2. **Thời gian** gửi và nhận ở ISO 8601 UTC (`2026-10-20T07:00:00Z`); FE hiển thị theo `Asia/Ho_Chi_Minh`.
3. **Khả dụng tính theo khoảng thời gian**, không theo tổng tồn kho (FR-P06). Kết quả khả dụng ở các API xem chỉ để tham khảo; kết quả cuối cùng được kiểm tra lại khi tạo đơn.
4. **Quyền sở hữu:** Customer chỉ đọc/ghi đơn của chính mình. Truy cập đơn của người khác trả `404` (không tiết lộ đơn có tồn tại).
5. **Idempotency:** `POST /rental-orders` và `POST /orders/{orderId}/payments` nhận header `Idempotency-Key` (UUID do FE sinh mỗi lần bấm xác nhận). Gửi lại cùng key trả lại kết quả lần đầu, không tạo đơn/giao dịch mới (NFR-05).
6. **Trạng thái đơn và trạng thái thanh toán là hai trường riêng** (`status`, `paymentStatus`) — FE không gộp thành một nhãn (FR-F09).
7. **Mã lỗi nghiệp vụ** nằm trong `errors` của `ApiResponse` với key `code` (xem [Phụ lục B](#phụ-lục-b-mã-lỗi-nghiệp-vụ)):

```json
{
  "success": false,
  "statusCode": 409,
  "message": "Thiết bị không còn đủ trong khoảng thời gian đã chọn.",
  "data": null,
  "errors": {
    "code": ["RESOURCE_UNAVAILABLE"],
    "items[1].quantity": ["Chỉ còn 1 Đệm hơi trong 24/10 – 26/10."]
  },
  "timestamp": "2026-10-22T03:05:00Z"
}
```

### 4.2. Danh sách sản phẩm

`GET /products` · **Auth:** Public

Trả sản phẩm `Active` có ít nhất một biến thể `Active` và có bậc giá. Khi truyền đủ `from` + `to`, mỗi item có thêm thông tin khả dụng trong khoảng đó.

**Query params**

| Param | Type | Required | Default | Mô tả |
|---|---|---|---|---|
| `pageNumber` | `int` | ✘ | `1` | |
| `pageSize` | `int` | ✘ | `12` | 1–100 |
| `search` | `string` | ✘ | | Theo tên sản phẩm, tên biến thể, SKU |
| `categoryId` | `guid` | ✘ | | |
| `from` | `datetime` | ✘ | | Thời điểm nhận dự kiến (UTC). Đi cùng `to` |
| `to` | `datetime` | ✘ | | Thời điểm trả dự kiến (UTC). Phải > `from` |
| `onlyAvailable` | `bool` | ✘ | `false` | Chỉ lấy sản phẩm còn ≥ 1 tài sản trong `from`–`to` |
| `minDailyPrice` | `decimal` | ✘ | | Lọc theo giá/ngày thấp nhất |
| `maxDailyPrice` | `decimal` | ✘ | | |
| `sortBy` | `string` | ✘ | `name` | `name` · `priceFrom` · `createdAt` |
| `sortOrder` | `string` | ✘ | `asc` | `asc` \| `desc` |

**Response `200 OK`** — Paged data, mỗi item:

```json
{
  "id": "5d3e…",
  "name": "Lều Naturehike P-Series 4P",
  "category": { "id": "0b6c…", "name": "Lều trại" },
  "primaryImageUrl": "https://…/nh-p4-grn-1.jpg",
  "shortSpecs": "4 người · 2,6 kg · chống nước 3000 mm",
  "priceFrom": 70000,
  "variantCount": 3,
  "availability": {
    "from": "2026-10-20T07:00:00Z",
    "to": "2026-10-23T07:00:00Z",
    "availableQuantity": 3,
    "isAvailable": true
  }
}
```

- `priceFrom`: giá/ngày thấp nhất trong mọi bậc của mọi biến thể đang bán.
- `availability`: `null` khi không truyền `from`/`to`. `availableQuantity` = tổng tài sản khả dụng của mọi biến thể trong khoảng.

**Lỗi**

| Status | Khi nào | Code |
|---|---|---|
| 400 | Chỉ có `from` hoặc chỉ có `to`; `to` ≤ `from`; `from` ở quá khứ | `INVALID_RENTAL_PERIOD` |

### 4.6. Kiểm tra khả dụng nhiều dòng

`POST /rental-availability` · **Auth:** Public

Dùng cho giỏ thuê: kiểm tra **đồng thời** mọi dòng, cộng dồn nhu cầu theo biến thể (một biến thể có thể xuất hiện ở dòng lẻ và trong combo — PRD §8.4). Chỉ đọc, không giữ tài sản. Dùng `POST` vì body có danh sách.

**Request body**

| Field | Type | Required | Validation | Mô tả |
|---|---|---|---|---|
| `rentalStartAt` | `datetime` | ✔ | > hiện tại | Thời điểm nhận |
| `rentalEndAt` | `datetime` | ✔ | > `rentalStartAt` | Thời điểm trả |
| `items` | `RentalItemInput[]` | ✔ | 1–20 dòng | |
| `items[].productVariantId` | `guid` | ✱ | Đúng một trong hai | Thuê lẻ biến thể |
| `items[].bundleId` | `guid` | ✱ | Đúng một trong hai | Thuê combo |
| `items[].quantity` | `int` | ✔ | 1–20 | |

```json
{
  "rentalStartAt": "2026-10-20T07:00:00Z",
  "rentalEndAt": "2026-10-23T07:00:00Z",
  "items": [
    { "productVariantId": "a17c…", "quantity": 1 },
    { "bundleId": "e44a…", "quantity": 1 }
  ]
}
```

**Response `200 OK`** — `data`:

```json
{
  "billableDays": 3,
  "isAllAvailable": true,
  "items": [
    { "index": 0, "isAvailable": true, "availableQuantity": 3, "message": null },
    { "index": 1, "isAvailable": true, "availableQuantity": 2, "message": null }
  ]
}
```

Khi thiếu: `isAvailable: false`, `message: "Đệm hơi chỉ còn 1 trong khoảng 24/10 – 26/10"`.

**Lỗi**

| Status | Khi nào | Code |
|---|---|---|
| 400 | Thời gian không hợp lệ; dòng có cả hai hoặc không có `productVariantId`/`bundleId` (BR-13) | `INVALID_RENTAL_PERIOD`, `INVALID_RENTAL_ITEM` |
| 404 | Biến thể / combo không tồn tại hoặc ngừng kinh doanh | `ITEM_NOT_FOUND` |

- `totalAmount` = tiền dịch vụ sau giảm (= `orders.total_amount`, quy ước PRD §8.7). `depositAmount` tách riêng. `totalPayable` = `totalAmount` + `depositAmount` — số khách chuyển khoản.

| Status | Khi nào | Code |
|---|---|---|
| 400 | Thời gian / dòng không hợp lệ | `INVALID_RENTAL_PERIOD`, `INVALID_RENTAL_ITEM` |
| 400 | Không có bậc giá phù hợp số ngày (BR-15) | `PRICE_TIER_NOT_FOUND` |
| 404 | Biến thể / combo không tồn tại | `ITEM_NOT_FOUND` |

### 5.6. Hủy đơn thuê

`POST /rental-orders/{orderId}/cancel` · **Auth:** Customer (chủ đơn)

1. `orders.status = Cancelled`, ghi `cancelled_at`, `cancel_reason`.
2. Phân bổ `Reserved` → `Cancelled` (giải phóng tài sản ngay).
3. Nếu đã thu tiền: tạo giao dịch hoàn (`payments.payment_type = Refund`, `original_payment_id` = khoản thu gốc, `status = PendingApproval`) theo số tiền tính lại tại thời điểm hủy. **Admin duyệt** mới chuyển sang `Pending` → `Succeeded` (ma trận quyền §3.2). `paymentStatus` chỉ đổi sang `Refunded` / `PartiallyRefunded` khi hoàn thành công (BR-33).

## Phụ lục C: Quy tắc tính tiền

Theo PRD §8.3, §8.7 (đề xuất [D], chờ chốt Q-04 / Q-12):

```
billableDays  = max(1, ceil((rentalEndAt − rentalStartAt) / 24 giờ))
dailyPrice    = giá của bậc có minDays ≤ billableDays ≤ maxDays (maxDays null = ∞)
lineAmount    = quantity × billableDays × dailyPrice
subtotal      = Σ lineAmount
totalAmount   = max(0, subtotal − discount)          → orders.total_amount
depositAmount = theo cấu hình cọc (D-1)              → rental_orders.deposit_amount
totalPayable  = totalAmount + depositAmount          (không lưu cột; dẫn xuất)
```

Ví dụ đơn TRK851204: 3 ngày · lều 80.000 × 3 = 240.000 · combo 60.000 × 3 = 180.000 → tiền thuê 420.000; cọc 800.000; khách trả 1.220.000.

Quyết toán cọc (§8.7):

```
depositHeld          = cọc đã thu thành công − cọc đã hoàn − cọc đã bù phí
validCharges         = Σ phí Assessed chưa quyết toán
depositToRefund      = max(0, depositHeld − validCharges)
additionalAmountDue  = max(0, validCharges − depositHeld)
```
